Antes de começar

O que precisa estar em mãos.

  • Domínio registrado (Registro.br para .com.br) com acesso ao painel de DNS.
  • VPS com Ubuntu 24.04 LTS, no mínimo 2 vCPU, 4 GB de RAM e 40 GB de disco. O build do Next.js usa bastante memória; com 2 GB ele trava.
  • Acesso SSH à VPS como root (ou usuário com sudo).
  • Repositório joaovictormc/finances no GitHub, branch main atualizada.
  • Chaves de Brevo, Groq (e, se for usar, Claude e Ollama) e Mercado Pago. As de IA e de pagamento também podem ser cadastradas depois, pelo painel admin.

Decisão: onde fica o banco de produção

A. No ZimaOS, via Tailscale

É a decisão registrada em docs/deploy.md. A VPS entra na rede Tailscale e acessa o Postgres e o Redis de casa.

Contra: se a internet ou a energia de casa cair, a produção cai junto. Cada consulta atravessa a internet.

B. Na própria VPSrecomendado

Postgres e Redis como serviços do EasyPanel, na mesma máquina da API. Mais rápido e sem depender de casa.

Contra: o backup passa a ser responsabilidade da VPS (passo 14).

1

Preparar a VPS

Atualizar, criar memória de troca e fechar portas.

ssh root@IP_DA_VPS

apt update && apt upgrade -y

# 4 GB de swap: evita o build do Next morrer por falta de memória
fallocate -l 4G /swapfile && chmod 600 /swapfile
mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab

# Firewall: SSH, HTTP, HTTPS e o painel do EasyPanel (3000, só até ele ganhar domínio)
ufw allow 22 && ufw allow 80 && ufw allow 443 && ufw allow 3000
ufw --force enable
2

Instalar o EasyPanel

Ele cuida do Docker, dos builds, dos domínios e dos certificados HTTPS.

curl -sSL https://get.easypanel.io | sh
  1. Abra http://IP_DA_VPS:3000 e crie a conta de administrador do EasyPanel.
  2. Crie um projeto chamado controlai.
  3. Em Settings → GitHub, conecte sua conta para o EasyPanel ler o repositório.
Depois do passo 3, dê um domínio ao próprio painel (ex.: painel.seudominio.com.br, em Settings) e feche a porta 3000: ufw delete allow 3000.
3

Apontar o domínio

No painel de DNS do domínio, registros do tipo A para o IP da VPS.

TipoNomeValorPara
A@IP da VPSlanding
AwwwIP da VPSredireciona para a landing
AappIP da VPSapp web
AapiIP da VPSAPI (web, mobile e webhooks)
ApainelIP da VPSEasyPanel (opcional)

Confira a propagação (pode levar de minutos a algumas horas):

dig +short api.seudominio.com.br
dig +short app.seudominio.com.br
dig +short seudominio.com.br

Os três devem responder o IP da VPS. O certificado HTTPS só é emitido depois disso.

4

Banco de dados e Redis

Siga só a opção escolhida no passo 0.

Opção A: ZimaOS via Tailscale

# na VPS
curl -fsSL https://tailscale.com/install.sh | sh
tailscale up            # abre um link para autorizar a máquina na sua conta

# testar se a VPS enxerga o Postgres e o Redis
apt install -y netcat-openbsd
nc -zv IP_TAILSCALE_DO_ZIMAOS 5432
nc -zv IP_TAILSCALE_DO_ZIMAOS 6379

Crie um banco só para produção, separado da homologação:

# no ZimaOS
docker exec -it NOME_DO_CONTAINER_POSTGRES psql -U postgres -c "CREATE DATABASE controlai_prod;"
DATABASE_URL="postgresql://USUARIO:SENHA@IP_TAILSCALE_DO_ZIMAOS:5432/controlai_prod?schema=public"
REDIS_URL="redis://IP_TAILSCALE_DO_ZIMAOS:6379/2"     # /2 = base separada da homologação

Opção B: na VPS (EasyPanel)

  1. No projeto controlai, + Service → Postgres. Nome: postgres. Anote usuário, senha e banco que ele gerar.
  2. + Service → Redis. Nome: redis.
  3. Na aba de cada um, copie o endereço interno (algo como controlai_postgres). Os outros serviços do projeto falam com eles por esse nome, sem abrir porta para a internet.
DATABASE_URL="postgresql://postgres:SENHA@controlai_postgres:5432/controlai?schema=public"
REDIS_URL="redis://default:SENHA@controlai_redis:6379"
O código funciona com Postgres comum: o TimescaleDB é opcional (docs/setup.md).
5

Gerar os segredos

No seu Mac. Guarde cada resultado num gerenciador de senhas.

openssl rand -base64 32   # BETTER_AUTH_SECRET
openssl rand -base64 32   # APP_ENCRYPTION_KEY
openssl rand -hex 32      # LANDING_REVALIDATE_SECRET
openssl rand -hex 32      # LANDING_PREVIEW_SECRET
APP_ENCRYPTION_KEY é para sempre. Ela criptografa as chaves de IA e do Mercado Pago gravadas pelo painel. Se mudar ou se perder, essas chaves deixam de abrir e precisam ser cadastradas de novo. Guarde uma cópia fora da VPS.
6

Serviço da API

Primeiro serviço a subir: o web e a landing dependem dele.

  1. + Service → App, nome api.
  2. Source: GitHub, repositório joaovictormc/finances, branch main.
  3. Build: Dockerfile, caminho apps/api/Dockerfile, contexto / (raiz do repositório).
  4. Environment: cole o bloco abaixo, trocando os valores.
  5. Domains: api.seudominio.com.br, HTTPS ligado, porta interna 3001.
  6. Ative o deploy automático a cada push na main.
# Banco e fila (passo 4)
DATABASE_URL="..."
REDIS_URL="..."

# Endereços públicos — sem barra no final
BETTER_AUTH_URL="https://api.seudominio.com.br"
NEXT_PUBLIC_APP_URL="https://app.seudominio.com.br"
LANDING_URL="https://seudominio.com.br"
LAN_ORIGINS=""

# Segredos (passo 5)
BETTER_AUTH_SECRET="..."
APP_ENCRYPTION_KEY="..."
LANDING_REVALIDATE_SECRET="..."
LANDING_PREVIEW_SECRET="..."

# Cadastro e e-mail
AUTH_REQUIRE_EMAIL_VERIFICATION="true"
BREVO_API_KEY="..."
EMAIL_FROM_ADDRESS="nao-responda@seudominio.com.br"

# Admin: só no primeiro deploy (passo 7), depois remova
ADMIN_BOOTSTRAP="true"
ADMIN_EMAIL="voce@seudominio.com.br"
ADMIN_PASSWORD="uma-senha-forte"

# Opcionais: também podem ser cadastradas no painel admin
GROQ_API_KEY=""
ANTHROPIC_API_KEY=""
OLLAMA_API_KEY=""
MERCADOPAGO_ACCESS_TOKEN=""
MERCADOPAGO_WEBHOOK_SECRET=""
Por que cada endereço importa: BETTER_AUTH_URL é o endereço da própria API e também a origem que o app mobile apresenta no login. NEXT_PUBLIC_APP_URL entra nos links dos e-mails, no retorno do Mercado Pago e na lista de origens aceitas no login do web. LANDING_URL libera a landing no CORS e é chamado ao publicar no editor.

Os workers (insights, lembretes, rotinas de assinatura) rodam dentro do processo da API. Não há serviço separado.

7

Migrations, dados iniciais e admin

O banco novo está vazio: criar as tabelas, as categorias padrão e a conta admin.

Opção A (banco no ZimaOS): rode do seu Mac, com Tailscale ligado, antes de abrir o app:

cd ~/Documents/GitHub/finances
read -rs "PGPASS?Senha do banco de produção: "; echo
export PROD_URL="postgresql://USUARIO:${PGPASS}@IP_TAILSCALE_DO_ZIMAOS:5432/controlai_prod?schema=public"
DATABASE_URL="$PROD_URL" pnpm --filter @finances/db exec prisma migrate deploy
DATABASE_URL="$PROD_URL" pnpm --filter @finances/db db:seed

Opção B (banco na VPS): no EasyPanel, serviço api → aba Console:

pnpm --filter @finances/db exec prisma migrate deploy
pnpm --filter @finances/db db:seed

Depois, no EasyPanel, reinicie o serviço api. Com ADMIN_BOOTSTRAP="true", ao subir ele cria a conta admin com o e-mail e a senha do passo 6.

Entre com o admin uma vez para confirmar, depois apague ADMIN_BOOTSTRAP, ADMIN_EMAIL e ADMIN_PASSWORD do serviço e faça redeploy. Ligado, ele redefine a senha do admin a cada reinício.
Nunca use o endereço do banco de produção como --shadow-database-url do Prisma: o banco de rascunho é apagado.
8

Serviço do app (web)

O navegador fala só com app.seudominio.com.br; o web repassa /api/* para a API pela rede interna.

  1. + Service → App, nome web, mesmo repositório e branch.
  2. Build: Dockerfile apps/web/Dockerfile, contexto /.
  3. Build args (entram no build; mudar exige rebuild):
API_INTERNAL_URL=http://controlai_api:3001
NEXT_PUBLIC_LANDING_URL=https://seudominio.com.br
  1. Environment:
API_INTERNAL_URL="http://controlai_api:3001"
NEXT_PUBLIC_APP_URL="https://app.seudominio.com.br"
  1. Domains: app.seudominio.com.br, HTTPS, porta interna 3000.
controlai_api é o endereço interno do serviço da API no padrão do EasyPanel (projeto_serviço). Confira o nome exato na aba do serviço api. Errado, o app abre mas nenhuma tela carrega dados.
9

Serviço da landing

Site de apresentação, com conteúdo editado no admin.

  1. + Service → App, nome landing, mesmo repositório e branch.
  2. Build: Dockerfile apps/landing/Dockerfile, contexto /.
  3. Build args:
NEXT_PUBLIC_APP_URL=https://app.seudominio.com.br
NEXT_PUBLIC_API_URL=https://api.seudominio.com.br
  1. Environment:
API_INTERNAL_URL="http://controlai_api:3001"
LANDING_REVALIDATE_SECRET="o mesmo valor da API"
  1. Domains: seudominio.com.br (porta interna 3002) e www.seudominio.com.br com redirecionamento para o domínio sem www.
O redirecionamento do www importa: a API só libera no CORS o endereço exato da LANDING_URL. Acessada pelo www, a landing não consegue atualizar os preços no navegador.

Conferir se está tudo no ar

Na ordem: se um falhar, os seguintes também falham.

curl https://api.seudominio.com.br/health        # {"status":"ok",...}
curl -I https://app.seudominio.com.br/login     # 200
curl -I https://seudominio.com.br               # 200
curl -I https://www.seudominio.com.br           # 301/308 para o domínio sem www
  • Cadeado de HTTPS válido nos três domínios.
  • Login com o admin em app.seudominio.com.br.
  • Cadastro de uma conta de teste: o e-mail de confirmação chega (passo 12, Brevo).
  • Na landing, a seção de planos mostra os preços.
  • No admin → Landing page, publicar uma alteração e vê-la no site em seguida.
  • No cadastro, os links de Termos e Privacidade abrem a landing (não localhost).

Configurar pelo painel admin

Tudo aqui fica no banco e não precisa de deploy.

  • Modelos de IA: cadastrar as chaves (validadas na hora) e escolher provedor e modelo de cada função.
  • Meios de pagamento: Mercado Pago (access token e webhook secret) e Pix (chave, nome e cidade do recebedor).
  • Preços dos planos: conferir Pro e Família em cada período.
  • Landing page: criar termos-de-uso e politica-de-privacidade com os textos de docs/legal/, marcando "Mostrar link no rodapé do site".
  • Promoções: cupons de lançamento e regra de indicação, se for usar.
12

Mercado Pago e Brevo

Integrações que dependem do domínio público.

Mercado Pago: webhook

  1. Em mercadopago.com.br/developers/panel/app, abra a aplicação → Webhooks → Configurar notificações → Modo produção.
  2. URL: https://api.seudominio.com.br/api/webhooks/mercadopago
  3. Eventos de assinatura: Planos e assinaturas (subscription_preapproval) e Pagamentos de assinatura (subscription_authorized_payment).
  4. Salve e copie a assinatura secreta para o admin → Meios de pagamento → Mercado Pago (webhook secret).
Sem Pagamentos de assinatura, as renovações mensais não chegam e quem continua pagando perde o plano no primeiro vencimento.

Brevo: autenticar o domínio

  1. No Brevo, Senders, Domains & Dedicated IPs → Domains → Add a domain: seudominio.com.br.
  2. Crie no DNS os registros que ele mostrar (código Brevo, DKIM e DMARC) e clique em verificar.
  3. Cadastre o remetente do EMAIL_FROM_ADDRESS (ex.: nao-responda@seudominio.com.br).

Sem o domínio autenticado, confirmação de cadastro, troca de senha e lembretes tendem a cair no spam ou nem ser entregues.

App mobile

O endereço da API é embutido no app no momento do build.

Em apps/mobile/eas.json, perfil production:

"production": {
  "autoIncrement": true,
  "channel": "production",
  "env": {
    "EXPO_PUBLIC_API_URL": "https://api.seudominio.com.br",
    "EXPO_PUBLIC_LANDING_URL": "https://seudominio.com.br"
  }
}
Regras do endereço da API (errar qualquer uma faz o login falhar):
  1. Sem barra no final e sem /api.
  2. Idêntico ao BETTER_AUTH_URL da API: o app apresenta esse endereço como origem no login, e a API só aceita origens conhecidas.
  3. Com https://.
cd apps/mobile
eas build --platform android --profile production   # .aab para a Play Store
eas build --platform android --profile preview      # .apk para instalar direto (aponta para a homologação)
Atualização sem loja (eas update): ela não lê o env do eas.json, e sim o apps/mobile/.env da sua máquina (IP local). Passe sempre o endereço na linha de comando: 
EXPO_PUBLIC_API_URL="https://api.seudominio.com.br" \
EXPO_PUBLIC_LANDING_URL="https://seudominio.com.br" \
  eas update --channel production --message "descrição"

Push no celular: credenciais do build com eas credentials (detalhes em docs/deploy.md, A.4).

Backup e rotina

O que fazer depois de tudo no ar.

Backup diário do banco (opção B)

# na VPS: descubra o nome do container do Postgres
docker ps --format '{{.Names}}' | grep postgres

mkdir -p /root/backups
crontab -e
# todo dia às 3h, guarda 14 dias
0 3 * * * docker exec NOME_DO_CONTAINER pg_dump -U postgres -Fc controlai > /root/backups/controlai-$(date +\%F).dump && find /root/backups -name '*.dump' -mtime +14 -delete

Copie os arquivos para fora da VPS de tempos em tempos (seu computador, Google Drive, S3). Backup que só existe na mesma máquina some junto com ela. Na opção A, faça o mesmo no ZimaOS.

Publicar uma versão nova

  1. Migration nova? Rode prisma migrate deploy no banco de produção antes do merge (passo 7).
  2. Merge na main: o EasyPanel reconstrói e publica os três serviços.
  3. Variável nova? Cadastre no serviço antes do merge.

Problemas comuns

Sintoma → causa mais provável.

SintomaCausa provável
Login no web não entra ou volta para a tela de loginNEXT_PUBLIC_APP_URL da API diferente de https://app.seudominio.com.br (com barra no final, http em vez de https).
App abre, mas as telas ficam sem dadosAPI_INTERNAL_URL do web errado; ele é lido no build, então corrija o build arg e faça rebuild.
Login no celular falha com erro de origemEXPO_PUBLIC_API_URL diferente do BETTER_AUTH_URL. Corrija o eas.json e gere build novo.
Landing mostra o conteúdo de fábricaLANDING_REVALIDATE_SECRET faltando ou diferente entre API e landing.
Landing sem preçosAcessada pelo www sem redirecionamento, ou LANDING_URL errado na API.
Links de Termos apontam para localhostBuild arg NEXT_PUBLIC_LANDING_URL do web ausente. Corrija e faça rebuild.
Build trava ou é encerrado no meioPouca memória: confira o swap do passo 1 ou aumente a VPS.
E-mails não chegamDomínio não autenticado no Brevo, ou EMAIL_FROM_ADDRESS não cadastrado como remetente.
Chaves do painel "não abrem" depois de um ajusteAPP_ENCRYPTION_KEY mudou. Volte o valor original.
Renovações do cartão não aparecemEvento Pagamentos de assinatura desmarcado no webhook do Mercado Pago.
Detalhes técnicos e alternativas (homologação, self-hosted, Docker Compose) em docs/deploy.md.
